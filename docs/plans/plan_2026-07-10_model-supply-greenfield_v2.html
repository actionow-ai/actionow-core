1目标

按设计 v2（docs/plans/draft_2026-07-10_model-supply-greenfield.md，已过独立对抗评审并吸收全部 Blocker/Major）绿地重构模型供给与接入架构：五实体供给模型（厂商/渠道/凭证池/模型/供给项）+ 单一适配器 SPI（DSL+代码双作者、一致性测试门）+ 参数感知路由（billing_relevant 强制过滤）+ 全强度任务中心（租约/事件流/回调双保险）+ 模型寻址任务 API（/v1/videos/generations 等 + /v1/tasks 族），整体替换现有 resource/upstream_channel/channel_model 三层与三轨适配器。绿地约束：不做长期兼容层与数据迁移；生产切换走「双面并存短窗→租户迁移→整体删除」预案（见 Approach），/v1/run 与 Dify 专用子系统在窗口结束后整体移除。

5方案要点

方向：绿地替换供给骨架（数据模型+适配器 SPI+任务中心+API 面），保留达标资产（µUSD 七法与 hold/settle、pre-commit 流式、熔断参数、route_group/tags 钉选、relay_trace、R2、audit、动态配置）。设计唯一真相 = 设计 v2 文档；本 plan 只定目标/边界/批次/切换预案/分工。

切换与回滚预案（生产在线约束，v0.0.11 租户内测运行中）：采用「双面并存短窗」而非兼容层——新五实体表与新端点独立部署，与旧 resource 三层/旧端点在同一服务内并存；旧端点窗口期原样存活、新旧互不桥接翻译。切换四步：①批次4 末新面全量上线（旧面未动，零停机）；②供给配置经批建工具在新表全量重建，内部租户（自家产品）先切新面灰度 ≥3 天；③发租户迁移通告，迁移窗（目标 1 周，内部租户可控）内新旧双活，切换日出新旧双账快照保对账连续性（账本 append-only 不迁移，新旧账本并存）；④迁移窗结束 + 观察期无致命缺陷 → 批次5 末删除旧端点/旧表/dify 子系统。回滚路径：删除动作前任何时点回滚=部署版本回退（旧代码在 git、旧表全程未动、旧账本未动），新表数据弃置不影响旧面；删除动作本身是最后一步且不可逆，执行前需 DRI 显式确认。

批次1 · 供给数据模型：五实体 schema 与仓储、参数契约结构化声明（supports/domain/map/fixed/unsupported + billing_relevant 标记）、可见性/BYOK/key 白名单改 model 维度、官方价目对接与 needs_pricing 闸、CRUD API+审计。

批次2 · 适配器 SPI：六切面接口与执行流水线（凭证注入后冻结）、签名器提升为共享切面、DSL 引擎与版本化装配、一致性测试门进 CI、既有 5 方言（openai/anthropic/gemini/volc/惠梦）迁移过门。与批次1 同期交错推进（单执行者下为交错 session），contracts 接缝于两批开工首日冻结（批次0 动作：IR/五实体的 zod 契约先行合入，之后只增不改）。

批次3 · 路由与执行规划器：参数感知候选过滤与排序、fetch_profile 四模式规划（direct 至多一次+独立长阻塞池）、慢操作纯服务端自动升格、并发闸门 min(offering, credential) 双维信号量、task 路由与同步对齐钉选/容错。依赖批次1+2。

批次4 · 任务中心、API 面与计费闭环：/v1/videos/generations 等资源风格端点 + /v1/tasks 族（查询/列表/取消/SSE）+ GET /v1/models 发现端点（member 面与 key 白名单依赖）、task_events 事件流（retention 受控）、租约恢复（仅可恢复 fetch 模式）、上游回调双保险（修 envelope 断链）、下游 webhook 事件信封、产物双轨、媒体字节路径加固（SSRF+流式管道）、幂等体指纹 409、计费闭环（estimated 标志+价格快照+对账报表）、@actionow/sdk 重生成（含 submit-and-wait）。批内预置砍刀（超限时先砍且验收相应后置）：public 轨可后置、webhook 退避档位固定 5 档不做可配。本批末执行切换预案第①②步。

批次5 · 运营面收口与旧世界删除：发现/批建/golden probe 双门、接入向导 UI 五步、下线与软删语义、对账自动化（官方渠道；可砍项）、integration/building-on skill 重写与租户迁移通告（切换预案第③步）、迁移窗后删除 /v1/run 与 dify 子系统（第④步，DRI 确认后执行）、全量 e2e 与文档。

研究输入：docs/research/research_2026-07-10_omni-gateway-model-onboarding-gap.html（issue TEA-1072）；设计评审报告 docs/research/research_2026-07-10_omni-gateway-gap.d/05-design-eval.md（4 Blocker/14 Major 已全部吸收进设计 v2，plan 评审人已抽查核实）；产品裁决 4 项（产物双轨/纯服务端升格/task 对齐钉选/对账降级）已由用户拍板并写入 v2。
