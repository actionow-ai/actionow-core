1目标

按设计 v2（docs/plans/draft_2026-07-10_model-supply-greenfield.md，已过独立对抗评审并吸收全部 Blocker/Major）绿地重构模型供给与接入架构：五实体供给模型（厂商/渠道/凭证池/模型/供给项）+ 单一适配器 SPI（DSL+代码双作者、一致性测试门）+ 参数感知路由（billing_relevant 强制过滤）+ 全强度任务中心（租约/事件流/回调双保险）+ 模型寻址任务 API（/v1/videos/generations 等 + /v1/tasks 族），整体替换现有 resource/upstream_channel/channel_model 三层与三轨适配器。绿地约束：不做数据迁移与旧 API 兼容，/v1/run 与 Dify 专用子系统整体移除。

5方案要点

方向：绿地替换供给骨架（数据模型+适配器 SPI+任务中心+API 面），保留达标资产（µUSD 七法与 hold/settle、pre-commit 流式、熔断参数、route_group/tags 钉选、relay_trace、R2、audit、动态配置）。设计唯一真相 = 设计 v2 文档；本 plan 只定目标/边界/批次/分工，不复述设计细节。

批次1 · 供给数据模型：五实体 schema 与仓储、参数契约结构化声明（supports/domain/map/fixed/unsupported + billing_relevant 标记）、可见性/BYOK/key 白名单改 model 维度、官方价目对接与 needs_pricing 闸、CRUD API+审计。

批次2 · 适配器 SPI：六切面接口与执行流水线（凭证注入后冻结）、签名器提升为共享切面、DSL 引擎与版本化装配、一致性测试门进 CI、既有 5 方言（openai/anthropic/gemini/volc/惠梦）迁移过门。与批次1 可并行起步，接缝以 contracts 单源锁定。

批次3 · 路由与执行规划器：参数感知候选过滤与排序、fetch_profile 四模式规划（direct 至多一次+独立长阻塞池）、慢操作纯服务端自动升格、并发闸门 min(offering, credential) 双维信号量、task 路由与同步对齐钉选/容错。依赖批次1+2。

批次4 · 任务中心与 API 面：/v1/videos/generations 等资源风格端点 + /v1/tasks 族（查询/列表/取消/SSE）、task_events 事件流（retention 受控）、租约恢复（仅可恢复 fetch 模式）、上游回调双保险（修 envelope 断链）、下游 webhook 事件信封与可配退避、产物双轨（signed 默认/public 画廊）、媒体字节路径加固（SSRF+流式管道）、幂等体指纹 409。依赖批次3。

批次5 · 运营面收口：发现/批建/golden probe 双门、接入向导 UI 五步、下线与软删语义、对账（官方自动/中转报表）、dify 与 /v1/run 清除、全量 e2e 与文档（integration skill 同步更新）。

研究输入：docs/research/research_2026-07-10_omni-gateway-model-onboarding-gap.html（issue TEA-1072）；设计评审报告 docs/research/research_2026-07-10_omni-gateway-gap.d/05-design-eval.md（4 Blocker/14 Major 已全部吸收进设计 v2）；产品裁决 4 项（产物双轨/纯服务端升格/task 对齐钉选/对账降级）已由用户拍板并写入 v2。
